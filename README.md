# 🎐 Rin9's Website

个人网站 —— 记录日常 + 成长故事 + 未来作品集。纯静态，GitHub Pages 免费托管。

## 🚀 最快的编辑方式：可视化编辑器

**双击 `start-editor.bat`**（或 `启动编辑器.bat`），浏览器会自动打开编辑器。

左边选板块，中间填内容，**右边实时预览**。改完点「保存到本地」写回文件，
再点「保存并发布」直接推到 GitHub，Pages 一分钟内自动上线。

### 编辑器能做什么

| 操作 | 怎么做 |
|---|---|
| 改文字 | 中间表单直接改，右侧实时更新 |
| 加一条内容 | 右上角「＋ 新增一条」 |
| 加标签 | 输入框里敲一下回车，标签会变成可删除的小圆片 |
| **加图片** | **把图拖到你想要的位置**（见下方「拖图放哪儿」），自动压缩成 webp |
| 换封面 | 作品集条目里的「拖图到这里设为封面」 |
| **调整板块顺序** | 侧栏「🧩 页面布局」，或点预览区上方「🧩 布局」直接拖 |
| **钉住 / 隐藏板块** | 布局面板的 📌 / 👁 按钮 |
| **改板块标题** | 布局面板的「板块标题」 |
| **撤销 / 重做** | 顶栏 ↶ ↷ 按钮，或 Ctrl+Z / Ctrl+Shift+Z |
| **调整条目顺序** | 拖条目左侧的 ⠿ 手柄，或用 ↑↓ 按钮 |
| **上传音乐 / 建歌单** | 侧栏「🎵 音乐库」 |
| 转格式 / 压缩图片 | 侧栏「🖼️ 图片工具」 |
| 改头像/简介/音乐 | 侧栏「⚙️ 基本资料」 |
| 删除 | 每条右侧的 🗑 按钮 |

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Z` | 撤销 |
| `Ctrl+Shift+Z` / `Ctrl+Y` | 重做 |
| `Ctrl+S` | 保存到本地 |
| `1` ~ `6` | 切换到第 N 个板块 |
| `空格` | 站点上播放/暂停音乐 |

撤销历史保留 60 步。连续输入同一处会合并成一步（不会一个字一个字地占历史）。

### 调整页面布局（需求 1）

**两种方式，改的是同一份配置：**

**方式一：在预览区直接拖（最直观）**

点预览区上方的「🧩 布局」按钮 →
预览区里每个板块右上角会出现手柄，拖动即可调整顺序；
📌 钉住（滚动时固定在顶部）、👁 隐藏。

预览区会自动变宽，方便拖动。

**方式二：在「页面布局」面板精确调整**

侧栏 →「🧩 页面布局」→ 板块顺序列表（↑↓ 移动、📌 钉住、👁 隐藏）
+ 板块标题编辑（标题 / 副标题）。

两种方式**实时双向同步**，改哪边另一边立刻跟着变。

### 音乐聚合器（需求 3）

**站点上的播放器**

点 Hero 里的「🎵 音乐」按钮，右侧滑出播放器面板：

- 进度条可拖动，显示当前时间/总时长
- 上一首 / 播放暂停 / 下一首 / 循环模式（列表循环 → 单曲循环 → 不循环）/ 音量
- 歌单下拉切换
- 歌曲列表点击即播，当前播放高亮
- 底部「🎧 听更多我推荐的音乐」跳到独立页面

空格键可以播放/暂停。

**音乐库管理**（侧栏「🎵 音乐库」）

- **上传**：把音频文件拖进虚线框，自动生成文件名、猜测标题与作者
- **试听**：点 ▶ 试听 6 秒
- **编辑 / 删除**：标题、作者、路径、封面都可改
- **歌单**：新建歌单，往里加歌/移出歌
- **外链推荐**：添加到 `music.html` 的推荐列表，点击跳外部平台

**独立页面 `music.html`**

「听更多我推荐的音乐」跳转到这里，分两块：

- **站内音乐** —— 封面卡片网格，点了直接播放
- **外链推荐** —— 跳转到网易云 / QQ音乐 / B站 等平台

音频文件**原样保存不压缩**（mp3/wav/ogg/m4a 都支持），
「保存到本地」和「保存并发布」都会把音频一起写进 `music/` 目录。

### 拖图放哪儿 —— 落点由鼠标位置决定

拖动的时候屏幕上会实时显示 **「→ 设为封面」** 这样的提示，
告诉你松手后图片会去哪。同时目标区域会高亮出来。

| 拖到哪 | 图片落到哪 |
|---|---|
| 某个条目的虚线框里 | 该条目的对应字段（封面 / 配图 / 照片） |
| 某个条目卡片上（不在框里） | 按条目类型智能判断：作品→封面，记录→配图，照片→照片 |
| 板块内的空白处 | 该板块新建一条：作品集→带封面的新作品，日常记录→带配图的��记录，照片墙→新照片 |
| 页面其他任何地方 | 照片墙 |

**照片墙不再是"默认收容所"**——只有你明确拖到那儿才会进去。

同一个板块里重复拖同一张图不会产生重复文件（按内容指纹去重）。

### 图片工具（侧栏「🖼️ 图片工具」）

- **格式选择**：WebP（最小，推荐）/ JPG（兼容性最好）/ PNG（无损保留透明）
- **长边上限**：不缩放 / 1200 / 1600（推荐）/ 2000 / 3000
- **质量滑块**：30%–100%，实时显示数值
- **试压一张看看效果**：左右对比原图和压缩后，显示省了多少
- **本次会话新加的图片**：列出每张的压缩前后体积、尺寸、原文件名
- **批量转换已有图片**：把 img/ 里还是 jpg/png 的老图批量转成 webp，
  并**自动更新 data.js / css 里的所有引用路径**。这是把原来 `tools/ingest.py`
  的能力搬进了编辑器
- **扫描孤儿文件**：找出 img/ 里没被任何地方引用的图片（重复拖图产生的副本就是这类）

压缩参数会记在浏览器本地，下次打开还是你上次的选择。

### 两个保存按钮的区别

- **💾 保存到本地** —— 写回你硬盘上的 `js/data.js` 和 `img/` 图片。
  第一次点会让你选一次文件夹（选网站根目录 `OoRin9oO.github.io`），之后浏览器记住。
  需要用 **Edge 或 Chrome**（Firefox 不支持直接写文件）。
- **🚀 保存并发布** —— 直接提交到 GitHub 并推送，线上自动更新，不用开终端敲 git。

### 首次使用「保存并发布」要先填令牌

侧栏「🚀 发布设置」→ 填 Personal Access Token：

1. GitHub → 右上角头像 → Settings
2. 左侧最下面 → Developer settings
3. Personal access tokens → Tokens (classic) → Generate new token
4. 勾选 `repo`（公开仓库勾 `public_repo` 就够），设个有效期
5. 复制那串 `github_pat_...` 粘进去，点「🔌 测试连接」验证

令牌只存在你本机浏览器的 localStorage，不会传到任何第三方。

## 老的办法：批量投递（需要处理很多张图时更省事）

图片丢进 `inbox/`，写 `inbox/manifest.json`，跑：

```bash
python tools/ingest.py
```

脚本自动压缩、规范命名、合并进 `js/data.js`、归档原图。
参数：`--dry-run` 预览不落盘，`--no-img` 只导文案。

单张图、少量改动，**直接用编辑器更快**，不用碰命令行。

## 怎么加内容（手动改 data.js）

所有内容都是数据，改 `js/data.js` 就行，不用碰 HTML。

**加一个作品** → 往 `works` 数组加：

```js
{
    title: "我的新项目",
    desc: "一句话说明这个项目做了什么。",
    status: "wip",                // done 已完成 / wip 进行中 / plan 规划中
    cover: "img/shot-01.jpg",      // 可选，封面图
    tags: ["JavaScript", "CSS"],   // 标签会自动汇总到筛选条
    links: [
        { label: "源码", url: "https://github.com/..." },
        { label: "演示", url: "https://example.com" }
    ]
}
```

**加一条日常记录** → 往 `notes` 数组加：

```js
{
    date: "2026-10-26",
    title: "标题",
    desc: "随手写点什么。",
    images: ["img/shot-02.jpg"]    // 可选，显示为小图组，可点击放大
}
```

**加一个里程碑** → 往 `milestones` 数组加（按时间倒序，最新的放最前）：

```js
{ date: "2026-10-26", title: "第一次...", desc: "描述", icon: "🎉" }
```

**加一张照片** → 往 `gallery` 数组加：

```js
{ src: "img/photo1.jpg", caption: "照片说明" }
```

**加一个常用链接** → 往 `links` 数组加：

```js
{ icon: "🎮", name: "steam", url: "https://steam.com" }
```

**换背景音乐** → 音频文件放进 `music/`，改 `js/data.js` 的 `profile.bgm`。
推荐 mp3（体积小），当前用的 `music/bgm.wav` 是临时生成的合成音。

**换头像 / 改个人信息** → 改 `js/data.js` 的 `profile` 字段。

## 图片命名规范

**格式：`字母-日期-字母`**，例如 `a-20261025-a.webp`

- 前一个字母 = 序号（a、b、c…按投递顺序）
- 中间日期 = 投递日期（YYYYMMDD）
- 后一个字母 = 序号重复，用于快速肉眼校验排序

这样命名的三个好处：

1. **不会撞名**——不同批次同一天投递也不会覆盖
2. **一眼看出顺序**——字母序就是展示顺序
3. **URL 安全**——纯 ASCII，GitHub Pages / CDN / 各浏览器都不用做转义

同一张图出现在多处（日常记录配图 + 照片墙）时共用同一个文件名，不会重复存。
编辑器按**内容指纹**去重，同一张图拖多次只会存一份。

## 图片显示规则

照片墙用 **CSS 多列瀑布流**，图片按**原始比例完整显示，绝不裁剪、不拉伸**：

- 竖图保持竖的，横图保持横的，方图保持方的
- 等比缩放只用于控制体积（长边上限 1600px），不改变宽高比
- 灯箱里同样完整显示，不会裁掉上下或左右

## 板块增删

想加一个新板块（比如「技能」「友链」）：

1. 在 `index.html` 里加一个 `<section class="section" id="xxx">`
2. 在 `css/style.css` 里加对应样式（照抄 `.works-grid` 或 `.milestone` 那块）
3. 在 `js/data.js` 里加数据，在 `js/main.js` 里加一个 `renderXxx()` 函数
4. 在 `js/main.js` 的 `renderProfile()` 旁边调用它
5. 导航栏加一行 `<a href="#xxx">名字</a>`

想**删掉**一个板块：把 `index.html` 里对应的 `<section>` 整块删掉，
再把 `js/main.js` 里对应的 `renderXxx()` 定义和调用都删掉即可。

## 图片建议

- 长边 1600px 以内最合适，再大徒增体积
- webp 格式画质/体积比最优，编辑器会自动转
- 带透明通道的 PNG 会保留为 PNG，不会被压成黑底 JPG
- 单张图控制在 200KB 以内，页面滚动会更顺
